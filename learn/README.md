# PsyConsult 源码学习地图

## 学习目标

读完这一页，你不需要立刻记住一堆名词，而要先完成四件事：

1. 知道这是一段怎样的学习旅程，以及终点是什么；
2. 按自己的时间，从 **3 天面试速成、7 天上手、完整源码路线**中选一条；
3. 知道每一部分只解决什么问题，不在目录里迷路；
4. 建立“先看现象，再问机制，最后进源码验证”的学习习惯。

> 学习完成的标志不是“文档看完了”，而是你能画出一次请求的旅程、找到关键实现、解释设计取舍，并用证据排查失败。

## 1. 这是一段怎样的旅程？

想象你刚接手一家夜间门诊的数字化改造。桌上有一份虚构病例，屏幕上有一个输入框。你发出问题后，不同岗位会接力：有人分诊，有人整理可能性，有人拟定后续方案，还有人检查药物风险。最后，结果不是等全部完成后一次性交付，而是像叫号屏一样持续更新。

这套指南不会先把零件名称倒给你。它会带你依次经历：

- **看见全程**：先知道问题从哪里来、答案到哪里去；
- **跟岗学习**：逐个理解分工者为何存在；
- **翻看交接本**：理解一轮与多轮之间如何保持连续；
- **检查安全门**：知道哪些输入能进来、哪些输出必须谨慎；
- **亲手值班**：运行、观察、故障演练、修改与验证；
- **完成交接**：能向面试官或新同事清楚讲明白。

### 生活类比：把系统当作一家协作门诊

- 用户的问题像一位来访者递交的情况说明；
- 请求入口像前台，负责核验身份与基本格式；
- 任务分派像分诊，决定先找哪个岗位；
- 专业处理像多科会诊，不同角色各管一段；
- 会话记录像交接本，让下一轮不必从头问起；
- 外部资料像资料室，需要时查证，而不是全靠记忆；
- 持续返回像叫号屏，让等待过程可见。

## 2. 我该选哪条路线？

| 路线 | 适合谁 | 学习顺序 | 你要交付的结果 |
|---|---|---|---|
| **3 天面试速成** | 已有开发基础，近期要面试或答辩 | 第 1 天：起点与背景；第 2 天：架构、协作与记忆；第 3 天：安全、项目表达 | 一张架构图、一段 60 秒介绍、三组取舍问答 |
| **7 天上手** | 即将接手项目，需要能运行和排障 | 每天推进一个主题组：背景 → 启动 → 架构 → 编排 → 知识/记忆 → 接口/界面 → 安全/实验 | 跑通一次虚构病例，完成一次可复现排障 |
| **完整源码路线** | 想系统掌握并能扩展项目 | 从学习起点顺序走到最终答辩，每部分都做源码定位、自测与实验 | 一份源码阅读笔记、一个经过验证的小改造、一套项目答辩材料 |

选择原则只有一个：**路线可以短，证据不能省。** 即使走 3 天路线，也要亲自画图、定位文件、说出失败时如何处理。

## 4. 这张地图落到项目里是什么？

现在再揭开实现名称：PsyConsult 是一个**精神科临床决策支持原型**。临床决策支持（Clinical Decision Support，简称 **CDS**）是给专业人员提供信息与建议的软件能力，不是替代医生作出诊疗决定。

项目把职责分成三层：

```text
front/clinical_cds/   页面与交互
        ↓
app/                  请求、鉴权、缓存与流式输出
        ↓
agent/                推理编排、专业角色、知识工具与记忆
```

主要实现包括 Vue 3（构建交互页面的前端框架）、FastAPI（定义 Python 网络接口的框架）、LangGraph（用节点、连线和状态组织任务的工作流库），以及 Redis（高速状态存储）、Milvus（向量检索服务）、Neo4j（关系图数据服务）等外部服务。此处只需建立“它们各有岗位”的认识；后续章节会继续用场景和源码加深理解。

一次典型请求可以从这些入口追踪：

```text
front/clinical_cds/src/App.vue
  → app/router/chat.py
  → app/service/chat_service.py
  → agent/core/workflow/graph_manager.py
  → agent/agents/
  → 逐段返回页面
```

## 6. 怎样读一节才不容易忘？

使用四步循环：

1. **先猜**：只看小节问题，画出自己的答案；
2. **再读**：用生活场景修正直觉；
3. **后证**：在代码、日志或测试中找到证据；
4. **复述**：合上文档，用 30–60 秒讲清输入、处理、输出和失败路径。

建议每次只改变一个条件。例如固定同一份虚构病例，只切换会话标识，观察连续性是否变化。单变量实验比“同时重启一切再碰运气”更容易找到因果。

## 7. 完成后怎样判断自己真的会了？

你应能独立完成以下验收：

- 从页面入口追到推理工作流，并指出每一层的职责边界；
- 解释任务为何会分支，以及三个专业角色如何顺序协作；
- 区分会话状态、长期事实与相似问题答案复用；
- 说明外部服务不可用时，哪些能力跳过、哪些主流程仍应继续；
- 观察持续返回的事件，而不只看最终文本；
- 使用虚构或脱敏数据，说明鉴权、输入校验、输出净化和人工复核边界；
- 运行后端测试、Python 语法检查和前端构建门禁；
- 用“问题—方案—取舍—证据—下一步”完成项目介绍。

## 8. 医疗学习边界是什么？

本仓库是软件工程学习与原型验证材料，输出不构成诊断、处方或治疗依据。练习只使用虚构或脱敏病例。遇到自伤/他伤风险、意识障碍或严重药物不良反应，应进入当地急救与专业处置流程，不能等待模型回答。

## 面试背板（30–60 秒）

> PsyConsult 的学习主线不是背技术名词，而是追踪一份虚构病例怎样经过入口校验、任务分派、专业角色协作、知识查证、会话记忆，再持续返回页面。我会先跑通最短闭环，再用源码和日志验证每一层，最后关注安全边界与优雅降级。系统的关键价值是把复杂推理拆成可观察、可恢复、可扩展的步骤；关键限制是它只是临床决策支持原型，不能替代医生，真实落地还需要医学验证、审计和数据治理。

## 常见误解

1. **误解：先把所有框架学完，才能读项目。** 纠正：先追一条真实请求，再按遇到的问题补概念。
2. **误解：看懂最终答案就等于看懂系统。** 纠正：还要观察路由、状态、工具、事件和失败路径。
3. **误解：路线越完整，学习效果越好。** 纠正：真正有效的是每一阶段都有可验证产物。
4. **误解：临床建议写得像真的，就可以直接使用。** 纠正：原型输出必须由专业人员审查，练习不得使用真实患者数据。
