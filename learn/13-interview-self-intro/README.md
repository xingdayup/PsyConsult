# 13 项目自述（STAR）

> 使用说明：60 秒版用于"介绍一个项目"开场；3 分钟版用于深挖前的主陈述。方括号处换成你的个人表达，数字都来自第 10 章实测。

## 60 秒版

**S**：我做了一个精神科临床决策支持系统的原型——医生用自然语言输入病例，系统给出鉴别诊断、治疗推荐和药物审查。

**T**：核心挑战是多轮连续推理：第二问"这位患者一线用药是什么"必须接得住第一问的病例，同时控制长对话的上下文成本。

**A**：技术上用 LangGraph 编排"路由 + 三个领域 Agent"的状态图，会话状态用 LangGraph Checkpoint + Redis 持久化；超过 16 条消息自动做"保留近 8 条 + LLM 摘要"的上下文压缩；跨会话的临床要点由 LLM 从会话历史提取后存 Milvus 做向量记忆；另外做了语义缓存，重复问题 0.27 秒直接返回。

**R**：全链路实测通过——多轮指代正确、缓存命中快约 200 倍、压缩后病例要点无损保留，后端 11 项测试通过。过程中还把第一版自研的 Redis 短期记忆整个重构成了 Checkpoint 方案，净删了 500 多行代码。

## 3 分钟版（在 60 秒版基础上展开）

1. **架构（约 45s）**：三层——Vue 前端 SSE 流式渲染；FastAPI 做鉴权/校验/缓存；agent 层是 LangGraph 状态图，路由节点判意图后进入"诊断→治疗→药审"流水线，各节点内层是 ReAct agent 按需调 Neo4j 图谱和 Milvus 向量工具。
2. **记忆体系（约 60s）**：三种存储各司其职——Checkpoint（Redis）管会话内状态，Milvus 长期记忆管患者临床要点（每 5 轮后台提取），Milvus 语义缓存管高频问题（自填充）。重点讲压缩节点：16/8 阈值、摘要保真（有实测对比）。
3. **演进与踩坑（约 45s）**：v1 自研记忆为什么被推翻（只存文本对、硬裁剪丢信息、提取链路断了没人发现）→ v2 Checkpoint 重构。挑 2 个坑讲：redis-stack 缺 RediSearch、配置漂移。
4. **结果与边界（约 30s）**：实测数字 + 明确的免责边界（原型、仅供参考、不入真实患者数据）。

## 反面清单（不要说）

- 不要说"用了 RAG/Agent"就停——每个名词后面接一句"它在我的系统里具体解决什么"
- 不要背数字出错：126 是首轮 SSE 事件数、0.273s 是缓存命中、6 是提取的临床要点数、16/8 是压缩阈值
- 不要声称"Text2Cypher 为主"或"向量检索按余弦排序"——与代码不符（第 07 章）
