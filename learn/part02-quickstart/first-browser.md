# 07｜第一次浏览器体验：从看到工作台开始

## 学习目标

按“看到什么 → 做了什么 → 系统怎样回应 → 背后叫什么”的顺序理解完整体验，不让陌生术语挡在第一步。

## 生活类比：先参观，再看设备说明书

第一次进入医生工作台，最重要的是知道病例写在哪里、结果从哪里出现、怎样新开一段会话。就像第一次坐进驾驶室，应先认识方向盘和刹车，而不是先读发动机协议。

下面这段正是**不适合初学者开场的反例**（信息基本准确，但一次堆入太多陌生名词，也是用户批评的那种写法）：

> 基于 **LangGraph 多智能体**的临床决策支持系统（Clinical CDS）：Vue 3 前端 + FastAPI 后端，通过 SSE 流式返回鉴别诊断、治疗推荐与药物相互作用审查建议。会话级状态由 **LangGraph Checkpoint + Redis** 管理，支持多轮临床问答的状态恢复与连续推理。

我们把它重写成递进故事：**医生打开工作台，写下一份虚构病例；接待窗口确认来信后，专家组依次整理诊断、治疗和用药风险；等待期间，进度和内容不断回到屏幕；再次追问时，资料室可按同一会话找回前文。** 先理解故事，再给设备命名。

## 图解


## 分步骤体验

先确保 API 正在 `5000` 端口运行，再开新终端。

**用途：** 安装工作台依赖并启动本地页面。  
**预期：** 终端给出 `http://localhost:5173`，浏览器打开后三栏工作台可见。

```powershell
Set-Location front\clinical_cds
npm ci
npm run dev
```

若后端配置了 Token，在本目录创建 `.env.local`：

```dotenv
VITE_API_BASE_URL=http://127.0.0.1:5000
VITE_API_AUTH_TOKEN=local-dev-token
```

然后按顺序观察：

1. 左侧点击“新建诊疗会话”；
2. 中间输入虚构病例，点击“发送”；
3. 先看到“已接收”等状态，再看到回答逐段增长；
4. 右侧用工作流和知识源提示理解当前阶段；
5. 在同一会话追问，再新建会话对比上下文差异。

到这里再给技术命名：页面由 Vue 构建，开发服务器由 Vite 启动，请求进入 FastAPI，专家流程由 LangGraph 编排，持续返回的文本事件叫 SSE。

## 项目真实实现

工作台真实行为见 [`front/clinical_cds/src/App.vue`](../../front/clinical_cds/src/App.vue)：

- 左侧维护会话列表，中间保存每个会话的消息，右侧展示静态流程说明；
- 请求 Body 是 `{query, session_id}`；
- `X-User-Id` 固定从当前 `userId` 发出；
- 只有本地 `VITE_API_AUTH_TOKEN` 非空时才添加 Bearer；
- 同一个页面会话复用同一 `session_id`；
- Markdown 先转换，再经 DOMPurify 净化后显示。

注意：右侧流程列表目前是说明性静态列表，不要把它误说成完整的实时追踪器。

## 源码二刷

Python 开发者可这样类比阅读：

- `ref(...)` 像“值变化后会自动刷新界面的变量”；
- `sendQuery()` 像一个异步 Python 客户端函数；
- `fetch(..., body=...)` 像发送 HTTP 请求；
- `reader.read()` 循环像 `async for` 消费流；
- `messagesBySession` 是按会话 ID 索引的字典。

先定位 [`sendQuery`](../../front/clinical_cds/src/App.vue)，只追 `query`、`requestSessionId`、`headers` 和 `response`，不要一开始阅读全部样式。

## 面试背板

> 工作台采用三栏交互：左侧管理本地会话，中间提交病例并增量显示内容，右侧解释流程与资料源。它用 POST 提交 `{query, session_id}`，始终发送 `X-User-Id`，按配置附加 Bearer，并读取 SSE 响应流。页面按会话保存本地消息，服务端则用相同 `session_id` 恢复 Checkpoint 上下文。

## 常见问题

**页面打开但发送失败怎么办？** 先看 API 终端是否运行，再看浏览器 Network 中 `/api/chat` 的状态码。

**修改 `.env.local` 后为什么没生效？** 停止并重新运行 `npm run dev`。

**为什么不能把前端 Token 当秘密？** 打包到浏览器的变量可被用户查看，只适合本地原型共享口令。

**右侧四阶段是否都来自实时事件？** 不是；当前 `pipelineStages` 是静态说明，消息状态会随服务事件更新。

## 自测

1. 不用技术名词描述一次浏览器体验。
2. 再把工作台、接待窗口、专家组分别换成真实技术名称。
3. 浏览器发出的 Body 有哪些字段？
4. 为什么先讲用户看到什么，再讲框架名？
