# 01｜为什么要做 PsyConsult

## 学习目标

理解项目要解决的不是“让模型代替医生”，而是把病例整理、资料检索和多专业核对组织成一条可观察的软件流程。

## 生活类比：一个人抱着四摞材料

值班医生面前有病历、诊断标准、治疗指南和药品资料。真正耗时的往往不是某一道题，而是在多份材料之间来回查找，还要确保诊断线索能接到治疗与用药风险。PsyConsult 像一名会分发任务的会诊秘书：不替专家签字，但让材料更快到达合适的人手里。

## 图解

```text
过去：医生 → 自己翻病历 → 自己找标准 → 自己查指南 → 自己核药

现在：医生 → 系统整理与分工
                 ├─ 诊断线索
                 ├─ 治疗建议
                 └─ 药物风险
              → 医生统一复核
```

## 分步骤体验

用一个虚构病例思考：

1. “近两周情绪低落、失眠、兴趣下降”先需要整理为症状与待补信息；
2. 有了鉴别方向，才适合讨论治疗路径；
3. 出现候选用药后，还要单独检查相互作用；
4. 每一步都应能说明资料来自哪里、哪里仍不确定。

这正是项目把一个大问题拆成三个领域步骤的原因。

## 项目真实实现

项目的专家组包含三条连续职责：

```text
鉴别诊断 → 治疗推荐 → 药物审查
```

入口协调者会判断当前问题应从哪一步开始。例如只问药物组合时，可以直接进入药物审查；如果从鉴别诊断开始，则继续走完后续流水线。定义见 [`agent/core/workflow/graph_manager.py`](../../agent/core/workflow/graph_manager.py)，三个领域实现位于 [`agent/agents/`](../../agent/agents/)。

项目还让资料缺失可见：Redis、Milvus 或 Neo4j 不可用时，相关记忆或检索能力会降级，而不是把“没有查到”伪装成“没有风险”。

## 面试背板

> 项目价值不在于封装一次大模型调用，而在于把鉴别诊断、治疗建议和药物审查拆成职责清楚的流水线，并接入会话状态与外部知识。这样更容易观察步骤、控制工具权限、定位故障，也更适合人工复核。

## 常见问题

**为什么不用一个大提示词一次回答？** 一次回答实现简单，但职责、工具和错误位置都混在一起，难以调试与治理。

**多步骤就一定更准确吗？** 不一定。它提高可组织性与可观察性，医学正确性仍要靠证据、测试和临床验证。

**为什么药物审查放最后？** 它需要结合前面形成的候选方案；直接问药物时又允许从该步骤进入。
