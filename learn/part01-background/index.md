# Part 01｜先认识这家“数字门诊”

## 学习目标

读完本页，你只需要建立一张朴素地图：PsyConsult 是给医生使用的**临床决策支持原型**，不是自动看病的 AI 医生；项目里有医生工作台、接待窗口、专家组和资料室四个角色。

## 生活类比：第一次走进门诊

想象你来到一家教学门诊。医生在工作台写下病例，接待窗口检查材料是否齐全，专家组按专业分工讨论，资料室提供既往记录、指南和药物关系。最终送回的是“供医生核对的会诊材料”，决定权仍在医生手里。

## 图解

```text
医生
  │ 写下虚构病例
  ▼
医生工作台 → 接待窗口 → 专家组 → 资料室
     ▲                    │
     └──── 分段送回建议 ──┘

输出：辅助材料，不是诊断书或处方
```

## 分步骤体验

1. 先说清项目为什么存在，而不是先背框架名。
2. 再确认哪些事系统可以辅助，哪些事必须由临床人员负责。
3. 最后学会用一段适合面试的语言介绍项目价值。

本篇暂时不要求启动程序，也不要求懂网页开发。

## 项目真实实现

四个生活角色分别对应仓库中的四块能力：

- **医生工作台**：接收病例并展示流式结果；
- **接待窗口**：校验身份与请求，组织返回过程；
- **专家组**：完成鉴别诊断、治疗推荐、药物审查；
- **资料室**：保存会话、检索文档与关系知识。

源码分别集中在 [`front/`](../../front/)、[`app/`](../../app/)、[`agent/`](../../agent/) 以及 Redis、Milvus、Neo4j 相关模块中。本页只认角色，不展开技术细节。

## 面试背板

> PsyConsult 是精神科临床决策支持原型。它把医生输入的病例交给分工明确的专家流程，再结合会话记录和知识资料生成辅助建议，并以流式方式送回工作台。它不替代医生，也不承诺直接诊断或开具处方。

## 常见问题

**这是聊天机器人吗？** 交互形式像聊天，但重点是有步骤的临床辅助流程。

**需要先会前端吗？** 不需要。本教程从 Python 开发者熟悉的函数、字典和异步流程逐步过渡。

**可以输入真实患者信息练习吗？** 不可以，只使用虚构或脱敏数据。
