# 11.2｜高频问题：先给一句人话，再给项目证据

每题都使用同一结构：**人话短答**先让面试官知道你的结论，**项目证据**证明不是背概念，**进阶追问**展示你知道取舍与边界。不要第一句话就钻进类名。

## 学习目标

- 对架构、状态、流、安全、缓存和 MCP 做短答；
- 每个结论都能落到当前源码；
- 识别面试官可能继续追问的取舍；
- 不把原型实现包装成生产能力；
- 形成可按岗位裁剪的问答卡。

## 类比：先给诊断方向，再展示检查依据

短答像“先判断是哪类问题”，证据像“检查结果”，追问像“为什么排除其他可能”。只有检查清单没有结论，会显得不会抽象；只有结论没有证据，会显得像背题。

## 真实实现

### Q1：为什么用多 Agent，不用一个大 Prompt？

**人话短答：** 因为诊断、治疗和药物审查职责与工具不同，拆开后更容易控制流程、观察阶段和单独测试。

**项目证据：** `AgentGraphManager` 有 orchestrator 和三个领域节点；入口可从中段开始，后续边是确定性流水线。诊断节点注册同义词、图谱和向量工具。

**进阶追问：** 拆分增加模型调用、延迟和状态复杂度；简单“检索一次再生成”不一定需要图。当前也不是自治 Agent 群或并行投票。

### Q2：LangGraph 在这里解决了什么？

**人话短答：** 它把模型决策和固定业务步骤放进一张可恢复、可流式观察的图。

**项目证据：** 条件边由 `next_agent` 选入口，普通边连接诊断→治疗→药物审查；compile 可传 checkpointer；`astream` 输出 custom/updates。

**进阶追问：** 若没有多轮状态和分支，普通 async 函数链可能更简单；框架价值来自显式控制，不是标签本身。

### Q3：外层图和 ReAct 有什么区别？

**人话短答：** 外层图决定科室之间怎么流转，ReAct 决定一个科室内部要不要调用工具。

**项目证据：** `graph_manager.py` 组装节点/边；领域 Agent 用 `create_react_agent(self.llm, self.tools)`。

**进阶追问：** prompt 限制工具次数不如确定预算、超时和 recursion limit 强；当前还可加强。

### Q4：请讲清三种状态和缓存。

**人话短答：** AgentState 是本次会诊工作单，checkpoint 是会话病历，长期记忆是跨会话可检索要点；缓存只是复用答案。

**项目证据：** `state.py` 定义字段；Redis saver 以 session/thread 恢复；MemoryManager 按 user 存取；cache 命中仍 `aupdate_state`。

**进阶追问：** 摘要是有损压缩；checkpoint 的用户级 namespace 需要专门隔离测试；缓存还要版本和失效策略。

### Q5：缓存命中为什么仍写 checkpoint？

**人话短答：** 快速返回不能让这一轮从对话历史里消失。

**项目证据：** `_record_cache_hit_turn()` 写入 HumanMessage 和 AIMessage；Redis 不可用时跳过并记录 warning 风险。

**进阶追问：** 应测试补写失败、重复请求幂等性、并发顺序和用户隔离。

### Q6：为什么选择 SSE，不用 WebSocket？

**人话短答：** 这个场景是发一次请求、服务端持续单向汇报，SSE 更贴合也更简单。

**项目证据：** `/api/chat` 返回 `StreamingResponse(text/event-stream)`；前端因需要 POST Body 和自定义 Header，使用 `fetch` 而不是 EventSource。

**进阶追问：** 网络 chunk 无帧边界；生产还要处理代理缓冲、断线、取消和显式 error 帧。双向高频通信更适合 WebSocket。

### Q7：前端怎样避免 SSE 半包？

**人话短答：** 先增量解码，把不完整文本留在 buffer，完整行才解析。

**项目证据：** `TextDecoder.decode(value, {stream:true})`、`buffer.split('\n')`、保留 `lines.pop()`。

**进阶追问：** 当前按单行 data 假设实现；通用解析器应支持 CRLF、多行 data、空行分帧和末尾残留。

### Q8：Milvus 和 Neo4j 为什么都要？

**人话短答：** 一个擅长找语义相近文本，一个擅长查明确实体关系。

**项目证据：** `query_vector_db` 查 `cloud_product_docs`；`query_knowledge_graph` 查疾病—症状—药物关系，并有关键词兜底。

**进阶追问：** 两者都可能为空或污染；应分开评估 Recall@K、图查询正确性和来源治理。

### Q9：当前鉴权做到什么程度？

**人话短答：** 它是原型入口门禁，不是完整登录和权限系统。

**项目证据：** 配置 token 时检查 Bearer，`compare_digest` 比较；`X-User-Id` 只做必填和正则；安全测试覆盖部分 401/400。

**进阶追问：** 格式合法不等于身份真实。生产要从 OIDC/JWT claim 派生主体，做资源授权、轮换、TLS、限流和审计。

### Q10：DOMPurify 解决 Prompt Injection 吗？

**人话短答：** 不解决；它清洗网页 HTML，提示注入发生在模型指令和数据边界。

**项目证据：** `marked.parse` 后 `DOMPurify.sanitize` 再进 `v-html`；Agent 工具与 prompt 是另一条链。

**进阶追问：** Prompt Injection 需要指令/数据分离、最小权限工具、参数校验、敏感动作人工确认和专门评测。

### Q11：系统怎样优雅降级？

**人话短答：** 可选基础设施失败时关闭对应增强能力，但明确损失，不假装完整健康。

**项目证据：** Redis saver 失败返回 None，图无状态；缓存/长期记忆初始化失败会禁用；摘要失败保留历史；后台提取失败只 warning。

**进阶追问：** 模型 Key 错、主模型故障、某些工具异常不能笼统保证；需要逐组件故障矩阵和可观测信号。

### Q12：MCP 在项目中是什么状态？

**人话短答：** 服务和发现管理代码已经有了，但还没接进应用主图。

**项目证据：** 有 `MCPManager`、JSON 配置和两个 clinical tools；`init_agent_system()` 没有实例化 manager，Agent tools 列表也没有 MCP 工具。

**进阶追问：** 应在 lifespan 连接，按名注入目标 Agent，失败用空工具降级，并测试发现、注入、关闭和 API 可达。

### Q13：如何测试有 LLM 的系统？

**人话短答：** 稳定逻辑离线测，模型只留少量固定数据评测和冒烟。

**项目证据：** 现有 API 测试 monkeypatch `stream_chat`，日志测试用 dummy cache；编译和前端构建独立做门禁。

**进阶追问：** 还需 mock 路由、假节点图测试、检索评测、版本固定和失败样本管理。

### Q14：项目性能如何？

**人话短答：** 当前有步骤耗时日志，但没有足以报告性能结论的基准数据。

**项目证据：** `chat_step`、Agent elapsed 和工具耗时存在；仓库没有 p50/p95、固定环境样本和并发报告。

**进阶追问：** 定义 accepted、首 content、done 三个时间，区分冷热缓存和依赖状态，多次采样报告分位数。

### Q15：系统能用于临床诊断吗？

**人话短答：** 不能把当前原型当作诊断或处方系统，输出必须由专业人员复核。

**项目证据：** README 与界面明确辅助参考；没有临床验证、医疗器械认证或真实场景安全证据。

**进阶追问：** 生产化还需要临床评测、治理、人工复核、高风险升级、隐私合规、审计和持续监控。

## 源码二刷

把每道题做成三张卡：结论卡、证据路径卡、追问卡。随机抽题时先在 15 秒内说短答，再用 30～60 秒给证据。若证据路径记不清，回到源码，而不是新增空泛名词。

## 面试背板

> 每题先给一句结论，再引用一处真实实现或测试，最后说代价和下一步。最重要的校准项是：MCP 未接主图，Bearer 只是原型门禁，格式合法不等于身份真实，当前没有临床准确率和生产性能指标。

## 常见误解

- **“短答越短越好，不用证据。”** 短答只是入口。
- **“追问时继续加名词。”** 应讲取舍、失败和验证方法。
- **“框架问题只讲定义。”** 要回到项目为何需要或是否过度设计。
- **“承认未测就结束。”** 还要给可执行测量方案。
- **“所有题都背同一段架构。”** 应针对问题选最小证据。

## 自测

1. 随机选 5 题，能否各在 15 秒内给人话短答？
2. 哪两题最容易夸大当前实现？
3. 怎样证明 cache 不是长期记忆？
4. 怎样用源码证明 MCP 未接入？
5. 面对性能追问，哪些数字绝对不能说？
