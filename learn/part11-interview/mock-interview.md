# 11.4｜模拟面试：从 30 秒介绍到连续追问

这是一套 35～45 分钟的模拟流程。练习时请真正计时、录音，并让同伴按评分表追问。答案示例不是逐字稿；你要保留结论和证据，换成自己的语言与真实贡献。

## 学习目标

- 在限时内完成 30 秒和 2 分钟介绍；
- 经受架构、状态、前端、安全、MCP 和指标连续追问；
- 发现并纠正口径漂移；
- 用 STAR 回答行为题；
- 用评分表形成下一轮改进动作。

## 类比：真实会诊演练

演练不是背标准答案，而是模拟信息不完整、追问改变方向和主动承认边界。面试官像会诊主持人：先听摘要，再选择最可疑或最有价值的点深挖。

## 真实实现

## 第一轮：开场（3 分钟）

**面试官：请用 30 秒介绍项目。**

候选人应覆盖：问题、方案、亮点、边界；最多 3 个技术名词。参考 [介绍脚本](./intro-scripts.md)，但不要超时。

**追问：你在其中具体负责什么？**

合格回答必须区分本人工作与仓库已有设计，例如：

> 我负责的是 `[你的真实范围]`。我亲自完成并验证了 `[具体模块/测试]`；`[其他部分]` 是项目既有实现，我做了阅读、联调或文档复盘，不把它算作个人交付。

红旗：把整个仓库都说成一人从零完成，却说不出 commit、测试和取舍。

## 第二轮：架构展开（8 分钟）

**面试官：请按一次请求讲主链路。**

期望顺序：页面收集 query/session→POST `/api/chat`→Header/Schema 边界→accepted→缓存→命中补 checkpoint 或未命中进图→custom/updates→SSE→前端流解析→done。

**追问 1：为什么缓存不是记忆？**

**人话短答：** 缓存复用计算结果，记忆为后续推理提供用户/会话事实。

**证据：** cache 保存问答，checkpoint 保存消息状态，长期记忆提取临床要点。

**追问 2：如果 Redis 挂了呢？**

**人话短答：** 单轮图可无状态运行，但多轮连续性和缓存命中补写会损失。

**证据：** checkpointer 工厂失败返回 None，图不加历史压缩。

红旗：回答“完全没有影响”。

## 第三轮：技术深挖（10 分钟）

**面试官：SSE 为什么不直接用 EventSource？**

**短答：** 需要 POST Body 和自定义 Header，所以用 fetch 读取响应流。

**证据：** `sendQuery()` 发送 JSON 和 Authorization/X-User-Id。

**继续追问：每个 read 是一条消息吗？**

**短答：** 不是，网络 chunk 与 SSE 帧无关。

**证据：** TextDecoder stream 模式和 buffer 保留半行。

**继续追问：当前解析器有什么局限？**

答出单行 data 假设、CRLF、多行 data、尾部残留和静默 catch 中至少两项。

---

**面试官：Milvus 和 Neo4j 是否重复？**

**短答：** 不重复，一个按语义找文本，一个按结构关系查询。

**证据：** `cloud_product_docs` 向量检索与疾病—症状—药物图查询。

**继续追问：如何评估？**

答出检索 Recall@K、图查询契约、回答忠实度，不能只说“看回答是否合理”。

## 第四轮：安全与边界（8 分钟）

**面试官：`X-User-Id` 通过正则，能否证明医生身份？**

**短答：** 不能，格式合法不等于身份真实。

**证据：** 浏览器可直接填写 Header；当前只有共享 token 与字符串校验。

**继续追问：生产怎么做？**

从已验证 token claim 派生主体，做资源级授权、session namespace、TLS、轮换、限流和审计。

---

**面试官：DOMPurify 是否解决提示注入？**

**短答：** 不解决，它只净化最终 HTML。

**证据：** marked→sanitize→v-html 位于前端展示层。

**继续追问：提示注入怎么办？**

讲指令/数据边界、最小权限工具、参数校验、人工确认、来源治理和评测；不要说“一个 prompt 就能完全防住”。

---

**面试官：MCP 用在哪里？**

**短答：** 当前有服务和管理器基础，但未接入主图。

**证据：** init 没有 manager，Agent tools 没有 MCP tool。

**继续追问：如何接？**

lifespan 连接、按名注入、失败空工具、关闭清理、API 可达测试。

红旗：为显得完整而谎称已接入。

## 第五轮：行为题 STAR（7 分钟）

**面试官：讲一次你发现设计隐患并修复或推动修复的经历。**

可选择真实故事：缓存命中导致会话断裂、Redis 降级、Markdown 安全，或 MCP 状态校准。结构要求：

- S：具体症状与证据；
- T：你的职责和约束；
- A：复现、取舍、实现、测试、回滚；
- R：可验证结果、未测项、下一步。

**压力追问：你说“效果更好”，具体好多少？**

合格回答：

> 我这里指工程语义被测试保护，而不是性能或临床效果提升。当前没有固定基准，所以不能给百分比；若要测，我会固定版本和样本，分别记录首内容、完整响应、误命中和路由指标。

## 第六轮：候选人反问（3 分钟）

选择 2 个：

1. 团队如何分别评估检索质量、生成忠实度和线上任务成功？
2. Agent 工具权限、人工审批和审计边界如何定义？
3. 状态、记忆和缓存各自的数据保留策略是什么？
4. 当前更关注首内容时间、完整成功率还是成本？
5. 失败样本怎样去标识并回流到评测集？

## 评分表（每项 0～2 分）

| 维度 | 0 | 1 | 2 |
|---|---|---|---|
| 问题表达 | 只念技术栈 | 有场景但模糊 | 问题和用户明确 |
| 主链路 | 顺序错误 | 大体正确 | 命中/未命中/SSE 完整 |
| 证据 | 无源码依据 | 偶尔引用 | 每个主张可落到代码/测试 |
| 取舍 | 只说优点 | 能说一个代价 | 能比较替代方案和适用边界 |
| 安全 | 夸大鉴权 | 知道部分限制 | 清楚格式/认证/授权/净化边界 |
| MCP | 误称已接入 | 说未接但证据弱 | 现状与接入方案准确 |
| 医疗边界 | 暗示自动诊疗 | 有免责声明 | 明确人工复核与未验证能力 |
| 指标诚信 | 编造数字 | 只说未测 | 未测 + 可执行测量方案 |
| STAR | 文件流水账 | 基本完整 | 责任、取舍、证据、下一步完整 |
| 时间控制 | 严重超时 | 略超时 | 30秒/2分钟可切换 |

总分 16 分以上再进入更强压力追问；低于 16 分先修最薄弱两项，不要一次重背全部。

## 源码二刷

模拟结束后只回看答错的问题：若 SSE 卡住，就重读 `stream_chat/sendQuery`；若状态混淆，就画 state/checkpoint/memory/cache 四格；若安全夸大，就重读路由测试和 session 隔离缺口；若 MCP 口径漂移，就找 init 与 tools 的断点。

## 面试背板

> 模拟时我先给结论，再给源码证据，最后讲取舍。遇到未测指标就明确未测并给方法；遇到 MCP、鉴权和医疗能力追问，宁可准确收住，也不把计划说成实现。

## 常见误解

- **“模拟面试只要默读答案。”** 必须计时、出声和接受打断。
- **“答错后重背全文。”** 应定位薄弱知识节点。
- **“压力追问必须给数字。”** 无证据时应拒绝编造。
- **“反问越多越好。”** 两个与岗位相关的问题足够。
- **“录音只看口头禅。”** 更要检查技术名词、证据和边界是否一致。

## 自测

1. 30 秒是否超时或超过 3 个技术名词？
2. 能否不看图讲完缓存命中与未命中路径？
3. 压力下会不会把 MCP 说成已接入？
4. STAR 的 Result 是否有真实证据？
5. 本轮最低的两个评分项，下轮准备怎样改？
