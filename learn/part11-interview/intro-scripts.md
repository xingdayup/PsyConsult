# 11.1｜项目介绍脚本：30 秒先收住，2 分钟再展开

介绍不是技术清单。30 秒版先让听众知道“什么问题、什么方案、什么亮点、什么边界”；只有得到时间，才在 2 分钟版逐层展开。这样面试官能控制深度，你也不容易在第一句话就丢失重点。

## 学习目标

- 掌握问题→方案→亮点→边界四句结构；
- 保证 30 秒版最多出现 3 个技术名词；
- 用 2 分钟版本逐层解释而不重复 README；
- 根据岗位切换后端、AI 工程和全栈侧重点；
- 不夸大 MCP、鉴权、医疗能力与指标。

## 类比：先给地图，再带人参观

第一次进医院的人先需要总平面图，不需要每台设备型号。30 秒是地图；2 分钟才走接待、会诊、档案和安全各层。技术名词只作为路标，不能代替故事。

## 图：四句结构

```mermaid
flowchart LR
  Q[问题: 非结构化信息与过程不可见] --> S[方案: 分阶段辅助决策]
  S --> H[亮点: 流式过程 + 状态连续 + 降级]
  H --> B[边界: 原型/人工复核/指标未测]
```

## 真实实现

## 30 秒版本（最多 3 个技术名词）

> 我做了一个精神科临床决策支持原型，解决病例描述零散、知识来源分散、分析过程不透明的问题。方案是把请求交给 **LangGraph** 编排的诊断、治疗和药物审查流程，由 **FastAPI** 通过 **SSE** 持续把阶段与结果推给医生工作台。工程亮点是缓存命中仍保持会话连续，部分基础设施不可用时可以降级。它只做辅助决策，不替代医生，也没有尚未完成的临床准确率和生产性能结论。

技术名词只有：LangGraph、FastAPI、SSE。没有在 30 秒中继续罗列 Vue、Redis、Milvus、Neo4j、ReAct、MCP。

### 30 秒结构拆解

1. **问题**：病例零散、知识分散、过程不透明；
2. **方案**：分阶段流程 + 实时工作台；
3. **亮点**：会话连续与依赖降级；
4. **边界**：辅助决策、指标未测。

若面试官只给一句话：

> 这是一个把精神科病例交给分阶段专家流程，并把过程实时展示给医生复核的临床决策支持原型。

## 2 分钟版本（逐层展开）

> 这个项目针对的是精神科问诊文本非结构化、指南和药物知识分散，以及单次模型回答过程不透明的问题。用户在前端工作台提交症状、病程或用药问题，页面保存会话并持续展示分析阶段和正文。
>
> API 层负责请求格式、入口 token 和用户标识检查，然后先查语义缓存。缓存命中会直接返回答案，但仍在 Redis checkpoint 可用时补写本轮问答，避免用户下一轮追问时上下文断裂；未命中才检索长期背景并进入 LangGraph。
>
> 图里由路由节点判断从鉴别诊断、治疗推荐还是药物审查开始。鉴别诊断节点能调用口语同义词、Neo4j 关系查询和 Milvus 文档检索，之后走固定的治疗和药物审查链。节点通过内部流发出开始、工具调用和正文片段，服务层把这些统一翻译成 SSE；前端用 fetch 读取流并增量更新同一个回答气泡。
>
> 状态上我区分图内 AgentState、按 session 保存的 Redis checkpoint，以及按 user 检索的 Milvus 长期临床要点；语义缓存是计算复用，不把它叫记忆。安全上目前是可配置共享 Bearer、ID 格式校验和前端 DOMPurify，仍不是完整身份授权。Redis 或部分 Milvus 能力不可用时会有对应降级，但模型本身错误不能笼统说都能降级。
>
> 项目目前是原型，不能用于自动诊断或处方；仓库虽有 MCP 管理器和临床工具服务，但尚未注入主图。我只用现有测试、编译和前端构建证明工程契约，没有编造临床准确率、并发或时延数字。

## 按岗位调整重点

### 后端岗位

把时间给 endpoint 边界、异步生成器、checkpoint、缓存命中补写、日志和降级；前端只讲流消费。

### AI/Agent 岗位

把时间给外层图与内层工具循环、RAG/图谱分工、三层状态、评测设计；主动说明工具调用与输出仍需复核。

### 全栈岗位

把时间给 POST SSE 契约、ReadableStream 缓冲、session 快照、Markdown 净化和跨层验证。

## 源码二刷

为脚本中每句话绑定证据：

- 分阶段流程 → `graph_manager.py`；
- 缓存补写 → `_record_cache_hit_turn()`；
- 三种状态 → `state.py/checkpointer.py/memory_manager.py`；
- 流式展示 → `stream_chat()` 与 `sendQuery()`；
- 安全边界 → `chat.py/test_chat_security.py/App.vue`；
- MCP 未接入 → `chat_service.init_agent_system()` 和 Agent tools 列表。

若一句话找不到证据，删掉或降级为“计划”。

## 面试背板

> 30 秒我只讲问题、方案、亮点、边界，控制在三个技术名词；2 分钟再按页面、API、编排、状态、安全逐层展开。所有结果都落到代码和测试，未完成的 MCP 与未测指标主动说明。

## 常见误解

- **“30 秒必须覆盖全部栈。”** 目标是让人理解，不是念依赖表。
- **“2 分钟要逐文件介绍。”** 应沿用户请求讲职责与取舍。
- **“边界最后不够有气势。”** 边界能建立可信度。
- **“降级代表任何依赖坏了都正常。”** 只能说具体已处理的依赖和损失。
- **“临床原型可以说辅助医生提高准确率。”** 没有临床研究不能这样说。

## 自测

1. 给 30 秒版标出恰好三个技术名词。
2. 删除所有框架名后，介绍是否仍能成立？
3. 2 分钟版是否解释了缓存命中补写？
4. 是否准确说明 MCP 未进主图？
5. 是否存在任何无证据的指标或医疗效果声称？
